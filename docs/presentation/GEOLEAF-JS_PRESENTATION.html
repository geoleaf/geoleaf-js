GeoLeaf-JS

Un client cartographique de terrain : une application de carte définie par un profil JSON, utilisée sur téléphone ou tablette pour consulter des données et les éditer, avec ou sans réseau. Le profil — pas le code — décide de quoi l'application parle.

Bibliothèque TypeScript · ESM Licence MIT, sans exception Ligne 3.x sur npm Bâti sur MapLibre GL JS 6 Agnostique de tout backend et de tout métier

Ce que c'est

Une carte métier se décrit dans un fichier, pas dans du code.

GeoLeaf-JS est une bibliothèque JavaScript qui transforme un profil JSON en application cartographique complète : couches, styles, thèmes, taxonomie de symboles, modules activés. Changer l'application, c'est changer le profil — pas recompiler.

Elle est agnostique de tout backend : elle tourne depuis des fichiers statiques, ou derrière n'importe quel serveur qui honore ses contrats. Les adresses de lecture, d'écriture et de téléversement sont déclarées dans le profil, pas codées dans la bibliothèque.

Ce n'est pas une bibliothèque SIG généraliste. Là où un outil généraliste est la meilleure réponse, GeoLeaf ne cherche pas à le concurrencer. Le périmètre qu'elle refuse est écrit plus bas, et il est aussi important que ce qu'elle fait.

À quoi ça sert

Le terrain n'a pas de réseau, et la donnée doit quand même être juste le soir.

Le problème que GeoLeaf-JS traite est celui d'un agent devant un objet de terrain, avec une tablette, souvent sans couverture. Il doit voir ce que le serveur sait de cet objet, corriger ce qui est faux, ajouter ce qui manque, et que sa saisie arrive au serveur, une fois et une seule, quand le réseau revient. Ce que l'objet représente — un équipement, une parcelle, une observation — relève du profil, jamais du code.

Deux formes d'usage démontrées

Le dépôt embarque deux profils de démonstration, qui servent de preuve exécutable plutôt que de capture d'écran :

Réseau d'éclairage public

Cinq couches — armoires, candélabres, réseau de câbles, secteurs, communes — avec terrain 3D, règles de style par altitude, et le cycle d'édition complet. C'est le profil qui exerce le plus de mécanismes à la fois.

Inventaire territorial large

Plus de quarante couches — aires protégées, occurrences naturalistes, parcours, séries climatiques mensuelles, réseaux, découpages administratifs — pour éprouver le passage à l'échelle et la variété des formats.

Ces deux profils sont des démonstrations, pas des références client. Une partie de leurs données est sous licence non commerciale : ils montrent le mécanisme, ils ne se livrent pas tels quels.

Les quatre axes

Quatre choses sont développées, et le reste est explicitement laissé de côté.

AXE 1

Les profils

Un profil JSON définit toute l'application. Dix schémas JSON Draft-07 le valident, et une gate refuse un profil non conforme avant qu'il n'atteigne un appareil.

AXE 2

Le cycle d'écriture hors-ligne

Une saisie est enregistrée localement sous identité client, mise en file, puis rejouée au serveur de façon idempotente au retour du réseau. Une modification faite sur une donnée périmée est détectée par un marqueur de fraîcheur.

AXE 3

Le hors-ligne préparé

Ce dont une journée de terrain a besoin — données et tuiles — est déclaré dans le profil et téléchargé à l'avance, au lieu d'être limité à ce qui a été consulté.

AXE 4

Le budget de poids

Ce qu'une page charge au démarrage est mesuré, plafonné, et traité comme une propriété du produit. Le dépassement casse la construction, il ne produit pas un avertissement.

Comment ça marche

Sept acteurs, et une seule chose à comprendre : la file locale est un chemin, pas un secours.

Ce que le schéma dit, et qu'il faut lire deux fois

  • Le profil est une entrée, pas de la configuration décorative. Il décide des couches, des styles, des thèmes, des modules actifs et des trois adresses serveur.
  • MapLibre GL JS reste à l'extérieur — dépendance peer, hors du paquet livré. GeoLeaf ne réimplémente pas de moteur de rendu et n'expose pas le moteur brut : il traduit un profil déclaratif en sources et couches natives.
  • Les modules s'ajoutent, ils ne s'imposent pas. Une application qui n'édite rien n'embarque pas l'éditeur ; une application toujours connectée n'embarque pas le moteur hors-ligne, qui arrive par chargement différé, en dehors du coût de démarrage.
  • Le passage par la file locale se décide sur la capacité de l'appareil, jamais sur l'état du réseau. Une saisie ne change donc jamais de chemin en cours de route — et c'est ce qui élimine la classe de bugs où la même saisie arrive deux fois, par deux chemins différents, sans que rien ne le détecte.

Ce qui est garanti

Les garanties sont bornées, et les bornes sont écrites.

Ce que GeoLeaf ne fait pas

Ce qui n'est pas développé est une décision, pas un retard.

  • Un outil de saisie générique. Formulaires, photos et édition de géométrie existent pour servir le cycle d'écriture et le modèle de données du serveur — pas comme un produit d'enquête autonome.
  • L'outillage GPS externe — récepteurs externes, analyse de traces.
  • Un SIG généraliste orienté bureau — analyse spatiale, liste croissante de formats, interfaces pensées pour le grand écran. Les modules de format qui existent sont maintenus comme les autres ; de nouveaux formats ne sont pas prévus.

Les modules sont écrits par l'équipe, pas par des tiers. Ils vivent dans le dépôt, contre un outillage de construction qui n'est pas publié. Écrire un module hors du dépôt n'est pas un chemin supporté : aucun générateur n'est publié pour ça.

Adopter

Un paquet npm, une dépendance externe, et un dossier qui se copie sur n'importe quel serveur statique.

Point État
Installation npm install @geoleaf/core maplibre-gl — ou un dossier prêt à copier sur un serveur statique (Apache, nginx, hébergement de pages).
Dépendances Une seule dépendance externe : MapLibre GL JS 6, fournie en peer et laissée hors du paquet. Le fichier livré ne contient aucune référence de module à résoudre — il se charge depuis n'importe quel serveur statique, sans table d'imports.
